Mână în mână · Aplicația web

Specificații și cerințe pentru partea de web, derivate din planul tehnic preliminar
Versiune 0.1 (draft)Data: 30.09.2026Client: browser (desktop + mobil)Backend: Firebase

1. Scop și rol în sistem

Aplicația web este o interfață pentru utilizator, echivalentă ca rol cu aplicația Android din plan: lecții, exersare, rezultate și progres. Ea nu accesează direct hardware-ul. Comunică exclusiv prin Firebase, iar Raspberry Pi 4B execută comenzile, rulează Computer Vision și ML și scrie rezultatele înapoi (planul, secț. 10).

Browser → Firebase (Auth + baza de date) → Raspberry Pi → PCA9685 → mână robotică · Webcam → CV → ML → evaluare → Firebase → Browser

Decizie asumată: analiza imaginii se face pe Raspberry Pi (webcam USB), deci site-ul nu folosește camera browserului și nu trimite imagini în cloud. Se pot trimite doar rezultatele.

Ciclul comenzii: pending → processing → completed sau error (cu error_message). Site-ul urmărește statusul în timp real și trece la pasul „Acum tu” abia la completed.

4. Cerințe funcționale

IDCerință
WEB-01Autentificare prin Firebase Auth; toate datele sunt asociate contului.
WEB-02Afișarea traseului de lecții cu niveluri deblocate în ordine și starea fiecărui nivel (blocat / curent / terminat).
WEB-03Încărcarea catalogului de semne din Firebase (MVP: 10–15 semne statice); adăugarea unui semn nu cere modificarea codului.
WEB-04La pornirea unei lecții se creează în robot_commands o comandă cu status = pending, o singură dată (fără dubluri la dublu-click sau reîncărcare).
WEB-05Afișarea în timp real a stării comenzii și a robotului (în așteptare, se execută, gata, eroare, offline).
WEB-06Indicarea clară a momentului în care utilizatorul trebuie să execute semnul, după finalizarea demonstrației.
WEB-07Preluarea și afișarea rezultatului din recognition: țintă, detectat, confidence, similaritate, feedback.
WEB-08Dacă predicted_sign = UNKNOWN (confidence sub prag), se afișează un mesaj de reîncercare, fără penalizare severă.
WEB-09Ecran de progres: număr de exerciții, istoric, evoluție pe semn.
WEB-10Feedback blând și motivațional (puncte, serie de zile, încercări) fără a modifica datele oficiale de recunoaștere.

5. Cerințe non-funcționale

IDCerință
WEB-N1Responsive: utilizabil pe telefon și desktop, cu suport pentru mod luminos și întunecat.
WEB-N2Compatibilitate: versiunile curente ale Chrome, Edge, Firefox și Safari.
WEB-N3Latență: actualizările de status apar în UI în aproximativ o secundă de la scrierea în Firebase (țintă de măsurat; nu include timpul mecanic al robotului).
WEB-N4Securitate: reguli Firebase care limitează fiecare utilizator la datele proprii; site-ul nu conține chei sau acces privilegiat.
WEB-N5Robustețe: tratarea pierderii conexiunii, a robotului offline și a timeout-ului; reluare fără a retrimite comanda deja executată.
WEB-N6Limbă și accesibilitate: interfață în română, contrast suficient, navigare de la tastatură, text alternativ pentru demonstrațiile vizuale.
WEB-N7Testabilitate: mod demo cu date simulate (ca prototipul actual), pentru testarea site-ului fără Pi și robot.

6. Situații alternative

  • Robot offline sau error → mesaj și buton de reîncercare.
  • Webcam indisponibil (raportat de Pi) → sesiune marcată ca eroare.
  • Servo în afara limitelor → comandă respinsă de Pi; site-ul afișează error_message.
  • Fără internet → banner de conexiune, fără comenzi noi.

7. Tehnologii propuse

  • HTML/CSS/JavaScript sau un framework la alegere (ex. React).
  • Firebase Web SDK: Auth și baza de date (Realtime Database sau Firestore, de decis).
  • Firebase Hosting pentru publicare.

8. Plan și criterii de acceptare

Plan (aliniat cu planul tehnic): prototip web cu date simulate (deja realizat) → integrare Firebase și robot în paralel cu Android (decembrie) → testare cu mai mulți utilizatori și măsurarea latenței (ianuarie) → stabilizare și documentație (februarie).

  • Un utilizator autentificat parcurge de pe web un ciclu complet: selectare semn → comandă → demonstrație → rezultat → progres salvat.
  • Rezultatele afișate pe web coincid cu cele din Android pentru aceeași sesiune.
  • Site-ul nu trimite nicio comandă dublă și tratează corect cel puțin: robot offline, confidence scăzut și pierderea conexiunii.

În afara scopului MVP: semne dinamice, certificare oficială a competenței, procesarea video în browser. De decis: Realtime Database sau Firestore, metoda de autentificare, dacă web și Android au aceleași funcții.
